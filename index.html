02 // Research Lab · Signature Console

Does the Model Understand the Dialect?

Compare regional-language text against Manak Hindi live in the browser. Inspect algorithmic BPE token IDs, grapheme clusters, and UTF-8 bytes separately—zero hardcoded mock splits.

Tathya // Research Console · Benchmark Preview v0.2
ENGINE: tathya-bpe-v0.2 · EVAL SET: IN PROGRESS
RESEARCH HYPOTHESIS

Regional language variation may affect LLM reliability through lexical coverage gaps, non-standard orthography, and semantic shifts. Tathya separates BPE tokens, integer token IDs, grapheme clusters, and UTF-8 byte lengths rather than assuming causality prior to controlled eval completion.

STAGE 02 · EVALUATION DESIGN (IN PROGRESS)

Controlled Experimental Setup: Identical civic welfare prompts paired in colloquial regional form vs. normalized Manak Hindi are evaluated under uniform system instructions and temperature controls.

Tracked Dependent Variables: (1) Factual accuracy against audited scheme PDFs, (2) Core entity preservation (scheme name & eligibility criteria), and (3) Answer completeness. Tokenization splits from Stage 01 are logged strictly as an observed input feature—not pre-asserted as sole causation.

Current Honesty Boundary: Live multi-LLM API execution is excluded from this static client bundle; published dataset scores will be released once the sample corpus reaches validation threshold.

STAGE 03 · CIVIC VERIFICATION ARCHITECTURE

1. Source Retrieval: Map query intent to official public-benefit circulars or departmental scheme documents rather than parametric memory alone.

2. Atomic Claim Extraction: Decompose candidate model responses into checkable assertions (eligibility income caps, required documents, application office).

3. Support vs. Unsupported Flagging: Surface unsupported claims visibly before serving answers in regional healthcare or ration card workflows.
